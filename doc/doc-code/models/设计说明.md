# models 域 —— 配置怎么变成可用的模型

## 1. 文件清单

| 文件 | 一句话职责 |
|---|---|
| `models/factory.py` | **工厂**：按 provider 分发，返回 BaseChatModel |
| `models/patched_openai.py` | **适配层**：统一创建 ChatOpenAI（OpenAI 兼容） |

## 2. 设计说明（调用链）

```
ChatModelConfig（config 域产出）
   │
factory.create_chat_model(cfg)          ← ① 工厂入口
   ├─ provider ∈ {openai-compatible, openai, zhipu}
   │     └──► patched_openai.create_openai_compatible_chat(cfg)
   │             └──► ChatOpenAI(
   │                   api_key / base_url / model / temperature)
   └─ 其他 provider ──► raise ValueError
   │
BaseChatModel（LangChain 统一接口）      ← ② 返回给 create_agent 使用
```

**关键设计**：
1. **OpenAI 兼容协议一统天下**：DeepSeek / 智谱 GLM / Ollama / LM Studio 都实现 /chat/completions，所以一套 ChatOpenAI 全盖住，不用每家写适配
2. **配置驱动分发**：factory 只认 `cfg.provider`，Agent 层（make_lead_agent）根本不关心用哪家模型
3. **扩展点（M6）**：新增供应商 = patched_xxx.py 加函数 + factory 加一个分支

## 3. 你问过的问题总结（Q&A）

**Q1：为什么 patched_openai 叫"patched"？**
A：原版为什么叫 patched：不同供应商在 extra body / 参数别名 / 流式格式上有细微差异，需要一个收敛层统一处理。M1 直接返回标准 ChatOpenAI（先留扩展点）；M6 做多供应商时再补真正的 patch 逻辑。

**Q2：DeepSeek 和 GLM 都能用？怎么切？**
A：都能。只改 config.yaml 三个字段：
```yaml
models:
  chat:
    provider: openai-compatible   # 或 zhipu
    base_url: https://api.deepseek.com/v1   # 或 open.bigmodel.cn/api/paas/v4
    model: deepseek-chat          # 或 glm-4.7-flash
```
代码零改动——这就是"配置驱动"的意义（ADR-003）。

**Q3：本地模型（Ollama/LM Studio）能接吗？**
A：能。base_url 指向本地 OpenAI 兼容端点（`http://127.0.0.1:11434/v1` 或 `http://localhost:1234/v1`），api_key 不能留空（SDK 要求非空，否则 Missing credentials——P-006）。
