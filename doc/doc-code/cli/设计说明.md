# cli 域 —— 一条对话怎么走完

## 1. 文件清单

| 文件 | 一句话职责 |
|---|---|
| `cli/__init__.py` | 包入口 |
| `cli/main.py` | `uv run agentflow` 的入口：装配所有组件 + 对话循环 |

## 2. 设计说明（完整装配链，从下往上）

```
uv run agentflow（pyproject 的 [project.scripts] 注册）
   │
main()
   ├─ ① 解析 --thread <id>（复用会话 or 新建）
   ├─ ② load_dotenv(项目根/.env)        ← 密钥（config 的 ${ENV} 靠它展开）
   ├─ ③ load_config()                   ← config.yaml → AppConfig（校验 api_key）
   ├─ ④ init_db(db_path)                ← 建表（sessions/session_messages）
   ├─ ⑤ create_sqlite_checkpointer()    ← 图状态检查点（SqliteSaver）
   ├─ ⑥ create_chat_model()             ← 模型工厂 → ChatOpenAI
   ├─ ⑦ make_lead_agent()               ← 主 Agent（含 system prompt 时间注入）
   ├─ ⑧ SessionRepository(conn)         ← 会话记录 repo
   │
   └─ 对话循环:
       你 > input
         → sessions.add_message(thread_id, "user", ...)      ← 存用户消息
         → agent.stream({"messages": [...]}, {thread_id})    ← 跑图（逐块流式）
         → 打印回复 → sessions.add_message("assistant", ...) ← 存回复
         → sessions.touch(thread_id)                          ← 刷新时间
       直到 exit
```

**为什么 --thread 能验证"会话可恢复"**：
```
第一次:  thread_id = 随机生成 → 对话 → 状态存入 SQLite
第二次:  uv run agentflow --thread <同一id>
         → checkpointer 按 thread_id 加载历史 → Agent 记得之前的话
```

## 3. 你问过的问题总结（Q&A）

**Q1：为什么 cli 是"装配器"而不是"业务逻辑"？**
A：原版思想——CLI/API 只是**入口层**，负责把组件组装好（配置/模型/检查点/repo）然后调用 Agent。真正的业务（图、工具、中间件）都在 agents/ 和 tools/ 里。M7 把 CLI 换成 FastAPI gateway 时，装配链几乎原样搬过去。

**Q2：gateway（app/gateway）是啥？和 cli 什么关系？（之前问过）**
A：gateway = **应用层的 API 网关**（FastAPI），面向外部世界（网页/IM/第三方调用）。M7 建 `backend/app/gateway/` 时，`make_lead_agent` 等核心装配会被它复用——cli 是"给人用的入口"，gateway 是"给程序用的入口"。

**Q3：对话循环里为什么先存 user 再跑图？**
A：业务记录（session_messages）与图状态（checkpoint）**两套存储**：先存明文记录（M7 前端展示用），再跑图（图内部状态由 checkpointer 存）。顺序不影响正确性，但记录要完整。

**Q4：CLI 不就命令操作台么？用在何处？（2026-09-28 收录）**
A：是"命令行操作台"，但准确说是**开发/调试入口**：
- **M1–M6**：CLI 是**唯一**能跟 Agent 对话的入口（所以验收用它）
- **M7 后**：正式入口变成 Gateway API（程序用）→ WebUI（用户用），CLI 退居**调试后门**（不启动服务直接测内核）
- **核心认知**：CLI / Gateway / WebUI 是**三个外壳、一个内核**——都调用 `make_lead_agent`。学 CLI 装配链 = 学内核用法，M7 原样搬进 FastAPI
- 具体用 3 处：① `uv run agentflow` 验收入口 ② `--thread <id>` 验证持久化 ③ 快速试功能

**Q5：为什么在 backend/ 下跑报"缺少模型配置"？（2026-09-28 收录）**
A：**config.yaml 定位 bug**——`load_config()` 默认找 `./config.yaml`（相对启动目录），从 backend/ 启动找不到根目录配置 → models=None。已修复：CLI 显式传 `project_root / "config.yaml"`（parents[5] 向上找），对齐原版 `Path(__file__).resolve().parents[N]` 思路。教训：配置定位不依赖启动目录（P-014）。

**Q6：为什么 Agent > 后空白不回复？（2026-09-28 收录）**
A：两个根因叠加（P-016）：① 智谱 thinking 模型流式内容在 `reasoning_content` 字段，langchain 只读 content → 全空（已修：zhipu provider 加 `extra_body thinking disabled`）；② langgraph stream chunk 是 `{'model': {'messages': [...]}}` 嵌套结构，直接 `chunk.get("messages")` 取不到（已修：`_iter_chunk_messages()` 递归取）。教训：流式输出结构要以实测 chunk 为准。
