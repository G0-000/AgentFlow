## 2. 设计说明（四块怎么协作）

```
thread_state.py（状态定义）
   class ThreadState(AgentState)         ← 继承官方基类
     messages（AgentState 自带，追加 reducer）
     thread_id（M1 自定义）

prompt.py（提示词）
   format_runtime_now_for_prompt()       ← "2026-09-28 周一 (UTC+08:00)"
   build_lead_agent_system_prompt()      ← 人格 + 当前时间

checkpointer/provider.py（持久化）
   sqlite3.connect(db_path, check_same_thread=False)
   → SqliteSaver(conn)                   ← 直接构造（3.x 的坑，P-010）

agent.py（装配）
   make_lead_agent(model, checkpointer, tools=None, system_prompt=None)
   → create_agent(model, tools, checkpointer, system_prompt)   ← langchain 官方
   → CompiledStateGraph（可 .stream()）
```

**一条对话的持久化原理**：
```
stream({messages}, config={"configurable": {"thread_id": id}})
   → 每执行一步，checkpointer 把当前 ThreadState 存 SQLite（按 thread_id）
   → 下次同一 thread_id 进入，自动加载历史状态 → "会话可恢复"
```

## 3. 你问过的问题总结（Q&A）

**Q1：ThreadState 为什么继承 AgentState 而不自己写 TypedDict？**
A：原版就是 `class ThreadState(AgentState)`（P-011 修正）。AgentState 官方自带 `messages + add_messages`（追加 reducer）——多轮上下文靠它累积，语义官方维护，不用自己实现。

**Q2：create_agent 到底从哪 import？（P-009）**
A：`from langchain.agents import create_agent`（原版同款）。**不要** `from langgraph.prebuilt import create_agent`——锁定版 prebuilt 1.0.8 只有 `create_react_agent`，create_agent 是 1.0.13+ 才有的名字。API 以实际锁定版本的导出为准。

**Q3：checkpointer 为什么直接 SqliteSaver(conn)？（P-010）**
A：langgraph-checkpoint-sqlite 3.x 的 `from_conn_string()` 返回上下文管理器（要 with 才拿到实例），不是可用实例。直接构造 `SqliteSaver(sqlite3.connect(...))`——原版注释也是这个思路（不用 from_conn_string 的 closing）。

**Q4：为什么"今天几号"能答对，却没有时间工具？（P-011）**
A：原版**没有**独立时间工具。时间由 `prompt.py` 的 `format_runtime_now_for_prompt()` 注入 system prompt，模型直接读到"2026-09-28 周一 (UTC+08:00)"——省一次工具往返。这是原版设计取舍，M1 照做。

**Q5：async_provider 现在用得上吗？**
A：用不上（M1 CLI 是同步的）。但它对齐原版入口名先建好，M7 FastAPI gateway 直接 `await create_async_sqlite_checkpointer()` + `setup()`。

## 4. M2 新增（中间件：title / thread_data）

| 文件 | 职责 | 为什么这样设计 |
|---|---|---|
| `agents/middlewares/__init__.py` | 中间件包入口 | 照原版 agents/middlewares/ 目录 |
| `agents/middlewares/title_middleware.py` | 首条消息 → 生成标题 → state["title"] | 照原版：标题是横向能力挂 AgentMiddleware；M2 用规则截断（不调 LLM，防 P-015 限流） |
| `agents/middlewares/thread_data_middleware.py` | 建线程数据目录 threads/{id}/user-data/{workspace,uploads,outputs} | 照原版：每个会话独立工作区（M3 文件工具的"地盘"） |

**接入方式**：`make_lead_agent(..., middleware=[TitleMiddleware(), ThreadDataMiddleware()])`
（注意参数名是**单数 middleware**，P-017）

**标题落库链路**：中间件生成 state["title"] → CLI 首轮后 `agent.get_state()` 读 → `sessions.update_title()` 落库 → 控制台打印 [标题]。
