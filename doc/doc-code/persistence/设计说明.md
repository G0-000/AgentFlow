# persistence 域 —— SQLite 唯一属主

## 1. 文件清单

| 文件 | 一句话职责 |
|---|---|
| `persistence/db.py` | 连接管理（自动建目录 / WAL / 外键 / Row 工厂） |
| `persistence/schema.py` | 表结构定义（SCHEMA_SQL：sessions + session_messages） |
| `persistence/bootstrap.py` | 幂等建表（executescript + commit） |
| `persistence/timestamps.py` | 统一时间戳（now_utc_iso） |
| `persistence/repositories.py` | **BaseRepository 基类**（统一 SQL 执行入口） |
| `persistence/session_repositories.py` | 会话 repo（create/get/delete/消息 CRUD） |

## 2. 设计说明（分层与调用链）

```
cli/main.py
   │  init_db(db_path)          ← ① 建表（schema.py 的 SQL）
   │  SessionRepository(conn)   ← ② 业务 repo（会话/消息记录）
   │
   ├── db.py: connect(db_path)  ← 连接配置（WAL/外键/Row）
   ├── schema.py: SCHEMA_SQL    ← 表定义（唯一处）
   ├── repositories.py: BaseRepository
   │     └─ _execute(写+commit) / _fetch_one / _fetch_all（读不 commit）
   └── session_repositories.py: SessionRepository(BaseRepository)
         └─ create / get / delete / touch / update_title
         └─ add_message / list_messages（session_messages 表）
```

**两张表的分工**（容易混的点）：

| 表 | 管什么 | 谁写 |
|---|---|---|
| `sessions` | 会话元信息（id/时间/标题） | SessionRepository |
| `session_messages` | 明文消息记录（user/assistant） | SessionRepository |
| checkpoint 表（langgraph 自己建的） | **图状态**（ThreadState 序列化） | SqliteSaver（agents 域） |

> 业务表（persistence）管"记录"，checkpoint 表（agents/checkpointer）管"状态"——**两套表，别混**；同一 thread_id 关联。

**关键设计**：
1. **唯一属主铁律**：全项目只有本域 import sqlite3，其他模块要数据都走 repo
2. **写 commit / 读不 commit**：基类统一约定，避免漏 commit 或白 commit
3. **幂等**：CREATE TABLE IF NOT EXISTS，重复启动不报错

## 3. 你问过的问题总结（Q&A）

**Q1：sessions 表和 checkpoint 表都是 SQLite，谁管谁？**
A：都在 `data/agentflow.db`（同一文件），但**归属不同域**：
- checkpoint 表 = `agents/checkpointer`（langgraph 官方建，存图状态）
- sessions/session_messages = `persistence`（你写的，存业务记录）
- 通过 thread_id 关联。M7 前端会话列表读业务表，恢复对话读 checkpoint 表。

**Q2：BaseRepository 的抽象方法为什么是 create 不是 insert？（P-008）**
A：重写注释时曾写错成 insert，子类实现的是 create → 无法实例化。抽象方法名必须与子类实现一致（create/get/delete）。

**Q3：SQLite 并发安全吗？**
A：连接开 WAL 模式（读写不互斥）+ 短事务。checkpointer 连接用 `check_same_thread=False`（langgraph 线程池可能跨线程访问，P-010 关联）。
