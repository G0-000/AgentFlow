# tools 域 —— M1 空壳，为什么

## 1. 文件清单

| 文件 | 一句话职责 |
|---|---|
| `tools/__init__.py` | 工具域包入口 |
| `tools/builtins/__init__.py` | 内置工具目录（**M1 空**） |

## 2. 设计说明

```
tools/（工具域：Agent 可调用的外部能力）
├── builtins/        ← M1 空壳（原版 60+ 工具，M2 开始学）
│   [M2] tool_catalog.py   工具注册表（schema/分组/按需加载）
│   [M2] tools.py          工具装配
│   [M2] middlewares/      工具中间件
│   [M4] host_direct/      宿主直连工具（read_file/terminal...）
```

**为什么 M1 没有工具**（这是学原版的关键取舍）：
1. 原版**没有独立时间工具**——时间靠 prompt 注入（见 agents 域 Q4）
2. M1 的目标是"最小 Agent 闭环"：模型 + 状态 + 持久化先跑通
3. M2 才学原版 tool_catalog：工具注册表、schema 自动生成、按需加载——那是工具的"正确打开方式"

**原版思想提前预告**：工具是**独立单元**（有 schema、有说明），Agent 只声明"我用哪些"——工具与 Agent 解耦，可复用、可单测。

## 3. 你问过的问题总结（Q&A）

**Q1：原版 tools/builtins 里到底有什么？**
A：原版 builtins 60+ 文件：browser_tool（浏览器）、code_execution_tool（代码执行）、web_extract_tool（网页抓取）、knowledge_tool、todo_tool、task_tool、send_message_tool 等。**没有 datetime_tool**（时间在 prompt，P-011）。

**Q2：M2 的工具目录会怎么学？**
A：读原版 `tools/tool_catalog.py`（注册/schema/分组）+ 2-3 个 builtins（如 web_search、file_read），实现自己的 tool_catalog + 至少 5 个内置工具，再挂 2 个中间件（thread_data/title）——M2 验收清单已建好。

## 4. M2 新增（工具目录 + 5 个内置工具 + 结果存取）

| 文件 | 职责 | 为什么这样设计 |
|---|---|---|
| `tools/tool_catalog.py` | 工具分层（7 tier + 中文标签 + resolve/enrich） | 照原版 273 行：分层是后续 gateway/UI/DB 同步的元数据基础 |
| `tools/tools.py` | `get_builtin_tools()` 延迟收集 + 去重 + 按 tier 排序 | 照原版 lru_cache + 函数内 import（启动快） |
| `tools/tool_result_store.py` | 工具结果存取（预览截断 _PREVIEW_MAX_CHARS） | 照原版：对话只显摘要，完整结果按 thread 存 |
| `tools/builtins/clarification_tool.py` | 澄清工具（return_direct=True） | 照原版 39 行：docstring 即说明书；return_direct 防模型循环 |
| `tools/builtins/todo_tool.py` | 会话内待办（内存） | 照原版：对话级 checklist，不进任务中心 |
| `tools/builtins/knowledge_tool.py` | 知识库 search/read/list + _format_hit | 照原版接口；M2 占位（未接 RAG，M5 接向量库） |
| `tools/builtins/plan_tool.py` | 计划 get/update/save | 照原版计划思想；M2 内存版 |
| `tools/builtins/fetch_url_tool.py` | 网页抓取 URL→文本 | 学原版 web_fetch 接口；M2 requests 简化版 |
