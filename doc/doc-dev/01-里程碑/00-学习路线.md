## 1. 项目全景（M0 期间顺带看懂）

### 1.1 一句话定位

EvoFlow 是一个 **LangGraph 驱动的长任务 Agent 运行时 + 控制平面**：Agent 会先澄清需求、出计划、拆解执行、失败恢复，全过程可观测、可人工干预。

### 1.2 技术栈

| 层 | 技术 |
|---|---|
| 后端运行时 | Python 3.12 · LangGraph 1.0.6+ · LangChain 1.2.3+ |
| API 层 | FastAPI（Gateway，端口 8001）+ LangGraph Server（端口 2024）+ Nginx（端口 2026） |
| 存储 | SQLite（唯一属主：`evoflow/persistence`） |
| 前端 | React 19 · Vite 6 · Tauri（桌面壳） |
| 工具链 | uv（Python）/ pnpm（前端）/ ruff（lint） |

### 1.3 三层架构

```
┌────────────────────────────────────────────────────────────┐
│  应用层  backend/app                                        │
│  (gateway: HTTP/SSE/WS 路由 · channels: 飞书/Slack/TG/企微) │
│            │ imports evoflow.*（单向，规则 R1）             │
│            ▼                                               │
│  核心层  backend/packages/harness/evoflow                  │
│  (agents · tools · knowledge · memory · collab · …)        │
│            │ 只通过"端口"(runtime/events.py) 反向调用应用层 │
│            ▼                                               │
│  持久化  evoflow/persistence（SQLite，唯一 DB 属主）        │
└────────────────────────────────────────────────────────────┘
```

**请求链路（一条对话怎么走）**：

```
用户输入
  → Nginx(2026) 分流
      ├─ /api/langgraph/* → LangGraph Server(2024) → lead_agent 图
      │     → 中间件链（70+ 个，按序执行）
      │     → Agent 循环：想 → 调工具（tools 目录）→ 看结果 → 再想
      │     → 需要时派子代理（subagents，并行 ≤3）
      │     → 结果经 SSE/流式回传
      └─ /api/* → Gateway API(8001) → models / mcp / skills / memory / uploads / artifacts …
```

### 1.4 三个入口图（`backend/langgraph.json`）

| 图 | 入口函数 | 用途 |
|---|---|---|
| `lead_agent` | `evoflow.agents.lead_agent.agent:make_lead_agent` | 日常对话 Agent（主入口，**第一个要读的文件**） |
| `goal_agent` | `evoflow.agents.goal.goal_graph:make_goal_graph` | 长任务（Plan/Goal）引擎 |
| `claude_code_chat` | `evoflow.agents.claude_code_chat_graph:make_claude_code_chat_graph` | Claude Code 风格会话 |

## 4. 核心思想提炼（看懂思想 = 重写有灵魂）

1. **分层与端口隔离（R1）**：核心层永远不能 import 应用层；反向需求走"端口 + 适配器"（`runtime/events.py`）。重写时照做——这是架构长期健康的关键。
2. **图编排 + 状态驱动**：一切运行时状态都在 `ThreadState`（及 mission_state 等），LangGraph 图是骨架，中间件是横切面。**状态先行，逻辑跟随**。
3. **中间件链**：横切关注点（记忆/工具/守卫/压缩/标题）全部中间件化，主循环保持干净。新增能力 = 新增中间件。
4. **工具目录化**：工具不是散落的函数，而是注册进 `tool_catalog` 的目录项——有 schema、有分组、有结果存储。**工具与 Agent 解耦**。
5. **持久化边界清晰**：业务表通过 `persistence/` repo 访问；LangGraph checkpoint 和 M6 独立 trace 库由专用模块管理。数据布局先行。
6. **双运行时分工**：LangGraph Server 跑 Agent 推理；Gateway 管外部世界（模型/技能/记忆/上传）。各自单测可独立跑。
7. **可观测性是功能**：trace、延迟、思考上下文、请求日志都是产品能力，不是事后补丁。
8. **本地/云端可切换**：模型（chat/embedding）都支持本地服务（Ollama/LM Studio/OpenAI 兼容）与云端，配置驱动、代码不动。

## 6. 学习技巧速查

- **找入口**：先 grep `make_`、`def main`、`router = `、`@router`，从工厂/路由出发。
- **看数据流**：优先读 `thread_state.py`、`models.py`、repo 层，数据长什么样决定了逻辑怎么写。
- **中间件顺序**：`agents/middlewares/__init__.py` 或装配处定义了顺序，这是理解横切面的钥匙。
