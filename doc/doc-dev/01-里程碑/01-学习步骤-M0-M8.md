```python
db_path = default_db_path()
parent = pathlib.Path(db_path).parent
parent.mkdir(parents=True, exist_ok=True)
conn = await aiosqlite.connect(db_path)
try:
    saver = AsyncSqliteSaver(conn)
```

白话解释：这是 `langgraph.json` 的 `checkpointer.path` 指向的工厂——一个无参 async context manager。对照原版它读 `app_config.checkpointer` 支持 memory/sqlite/postgres 三后端；AgentFlow 当前固定落 `data/agentflow.db`，这是"工厂签名对齐、内部后端裁剪"。

**片段 1：lru_cache + 函数内 import 的延迟收集**（`/Users/main/AgentFlow/backend/packages/harness/agentflow/tools/tools.py:60-86`）

```python
@lru_cache(maxsize=1)
def get_builtin_tools() -> tuple[BaseTool, ...]:
    """收集全部内置工具（延迟加载：函数内 import，照原版）。"""
    from agentflow.tools.builtins.clarification_tool import ask_clarification_tool
    from agentflow.tools.builtins.dispatch_tool import dispatch_subagents
    # ... 其余 7 个工具同样函数内 import
    return (ask_clarification_tool, todo_tool, knowledge_tool, plan_tool,
            fetch_url_tool, terminal_run, read_file, write_file, dispatch_subagents)
```

白话解释：为什么 import 写在函数里？因为 9 个工具模块里有 requests、subprocess 这类重量依赖，模块级 import 会让 CLI 启动变慢。`lru_cache(maxsize=1)` 保证只收集一次。**docstring 就是工具的说明书**——模型靠每个工具的 docstring 决定"什么时候该调它"。

**片段 2：目录收尾 = 去重 + 按 tier 排序**（`/Users/main/AgentFlow/backend/packages/harness/agentflow/tools/tools.py:89-103`）

同名工具只留第一个，再按 runtime → core → workspace → plan → goal → optional → retired 排序。这就是原版 tool_catalog 的"分层思想"简化版：工具不是散落函数，而是注册进目录的带 schema、带分层的条目。

```python

_impls: dict[str, Any] = {}


def register(key: str, impl: Any) -> None:
    """在 key 下注册一个应用层适配器（幂等：重复注册覆盖）。"""

        _impls[key] = impl
```

**片段 3：AgentFlow 学习版 streamSSE（两段式流式核心，`evopanel/src/lib/api-client.js`）**

```js
export async function streamSSE({ message, threadId = null, onDelta, onDone, onError, onCreated }) {
  // ① 创建 run（两段式第一步）——响应带 run_id + thread_id
  const run = await request('/runs', { method: 'POST', body: { message, thread_id: threadId } })
  onCreated?.(run)  // 新会话在这里回填 thread_id
  // ② 打开 SSE 流（GET /api/runs/{id}/stream）
  const resp = await fetch(apiUrl(`/runs/${run.run_id}/stream`))
  if (!resp.ok || !resp.body) { onError?.(`流打开失败 HTTP ${resp.status}`); return }
  const reader = resp.body.getReader()
  const decoder = new TextDecoder()
  let buffer = '', eventName = ''
  for (;;) {
    const { done, value } = await reader.read()
    if (done) break
    buffer += decoder.decode(value, { stream: true })
    let sep
    while ((sep = buffer.indexOf('\n\n')) !== -1) {   // SSE 帧以空行分隔
      const frame = buffer.slice(0, sep); buffer = buffer.slice(sep + 2)
      for (const line of frame.split('\n')) {
        if (line.startsWith('event:')) eventName = line.slice(6).trim()
        else if (line.startsWith('data:')) {
          const payload = JSON.parse(line.slice(5).trim())
          if (eventName === 'delta') onDelta?.(payload.delta ?? '')
          else if (eventName === 'done') onDone?.(payload.response ?? '')
          else if (eventName === 'error') onError?.(payload.error ?? '未知错误')
          eventName = ''
        }
      }
    }
  }
}
```

白话解释：学习版把原版 ChatApp 的流式消费抽成一个函数——两段式（先 POST 建 run 再 GET 流），手写 ReadableStream 逐帧解析 SSE（`\n\n` 切帧、`event:`/`data:` 行级匹配）。`onCreated` 回调解决"新会话 id 从哪来"（POST /runs 响应自带 thread_id）；`onDelta` 逐块追加实现打字机。这是验收点 2（流式回复）的核心。

```python
async def login(request: Request, body: LoginBody) -> dict:
```

## 附录 D — 学习方法建议

1. **对照原版重写的节奏**：每个里程碑都按"读原版文件清单 → 对照 AgentFlow 已落地代码 → 跑验证命令"三步。读原版是为了想清楚设计，不是逐行翻译；AgentFlow 每一步都刻意裁剪（目录照搬、文件砍 90%+）。
2. **不要跳步**：M1 的 checkpointer 是 M5 断点恢复的前提；M2 的工具目录是 M4 派发工具的前提；M6 的 JWT 是 M7 网关鉴权的前提。跳步会在后面踩同一坑两次。
3. **遇到语义对不上时**（比如 scheduler、automation），先查附录 A 的差异总表和 `doc/doc-code/*/语义对齐说明.md`——先确认"两边本来就不是一回事"，再决定是对齐还是记录差异。
4. **测试即契约**：每个里程碑的测试文件（`packages/harness/tests/`）断言的就是该模块该有的行为；改实现前先读它断言什么。
5. **诚实原则**：M5 的 goal_graph 句柄、M7 的空 runtime_adapters 都是"声明位置已就位、真实实现后置"——不伪造已编译图、不假装已接线。后续补齐时替换/填充即可。
