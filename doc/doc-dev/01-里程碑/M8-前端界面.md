## 3. 关键机制

1. **两段式 SSE 流式**（聊天页核心）：`POST /api/runs`（拿 run_id + thread_id）→ `GET /api/runs/{id}/stream`（消费 delta/done/error 事件）。`onCreated` 回调回填会话 id；`onDelta` 逐块追加实现打字机。
2. **登录 = localStorage token**：JWT 7 天过期（后端 exp 控制）；前端登录成功存 token → reload → main.js 登录态 gate 进主界面。JWT 校验中间件为 M8.1 增强（当前接口全开放）。
3. **模型存 SQLite 而非 config.yaml**：页面增改模型/设默认 → gateway_models 表 → 默认 runner 每次调用现场 `get_primary()`——**不重启代码，下次对话用新模型**。
4. **R1 端口装配不变**：create_app 仍以 `register_runtime_adapters()`（幂等）开头，M8 未破坏三层架构。

## 4. 契约差异（对照 EvoFlow v1.1.0）

| 面 | EvoFlow v1.1.0 原版 | AgentFlow 学习版 | 说明 |
|---|---|---|---|
| 鉴权 | API token 体系（`/api/auth/token` 直发 + whoami 验证，无密码登录） | `POST /api/auth/login`（JWT，7 天 exp） | 学习版教学选择；原版 token 体系列 M8.1 对齐方向 |
| runs | `GET /api/langgraph/runs`（org 鉴权管理面） | `POST /api/runs` + `GET /api/runs/{id}/stream`（两段式 SSE） | 学习版把"发消息→流式收"做成最小契约 |
| models | `/api/models` + `/api/models/primary` 子路径 + invoke 端点 | `/api/models` + `PATCH/DELETE /api/models/{name}`（is_primary 字段） | M7 ModelStore 设计延续 |
| threads | `GET/DELETE /api/threads`（删线程本地数据 + 鉴权） | `GET/POST /api/threads` + `DELETE /api/threads/{id}`（会话壳 CRUD） | 前缀一致；学习版补创建/列表 |
| 前端工程 | zcode 五体系 + Tauri 壳 + ChatApp.tsx 16879 行 | 薄壳单页 React + Vite（浏览器 Web） | 用户既定接受的学习版蓝图 |
