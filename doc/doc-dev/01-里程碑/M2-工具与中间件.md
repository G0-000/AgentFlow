# M2 —— 工具目录 + 中间件雏形

> **一句话目标**：让 Agent 从"只会聊"升级到"会调工具"——工具注册表、5 个内置工具、
> 工具结果存取、2 个中间件（自动标题 / 线程数据目录），并在 CLI 里可见、可验。
> 前置：M1 验收 5/5 已过（CLI 能真实对话 + 会话持久化 + 流式输出已修通 P-016）。

## 1. M2 做什么（用户视角）

| 能力 | 之前（M1） | 之后（M2） |
|---|---|---|
| Agent 调工具 | 无工具，只会纯对话 | 能**按场景自动选工具**（澄清/待办/知识库/计划/抓网页） |
| 输出方式 | 流式已通（P-016 修好） | 工具结果也走流式回传 |
| 会话标题 | 无（sessions.title 为空） | **自动生成标题**（第一条消息后） |
| 工具结果 | 无 | 有存取层（供 UI/后续引用） |

## 4. 分步实施（每步有验收小点）

### Step 1：工具目录分层 `tool_catalog.py`
- ToolTier 7 档 + 中文标签 + `TOOL_TIER_ORDER`
- `normalize_tool_name` / `resolve_tool_tier`（本地 `TOOL_TIER_MAP` 硬编码 5 个工具的分层）/ `tool_tier_label_zh` / `enrich_tool_catalog_fields`
- 自测：`resolve_tool_tier("ask_clarification") == "core"`

### Step 2：工具收集 `tools.py`
- `get_builtin_tools()`：lru_cache + 函数内 import 5 个工具 → tuple
- `_finalize_tool_catalog`：按 name 去重 + 按 tier 排序
- `get_available_tools()`：返回最终可用工具列表
- 自测：len(5)、名字唯一、无重复

### Step 3：5 个内置工具 `builtins/`
- `clarification_tool.py`（照原版 39 行）
- `todo_tool.py`（内存待办：add/list/update/delete）
- `knowledge_tool.py`（search/read/list 接口 + 占位实现）
- `plan_tool.py`（会话计划：get/update）
- `web_fetch_tool.py`（URL → 文本）
- 自测：每个工具 `.name`/`.description` 非空；docstring 写清楚"何时用"

### Step 4：工具结果存取 `tool_result_store.py`
- `ToolResultStore`（内存 dict：thread_id → tool_call_id → result）
- `summarize_tool_result(text)`：截断预览（学原版 _PREVIEW_MAX_CHARS）
- 自测：存取 + 截断

### Step 5：中间件 `agents/middlewares/`
- `title_middleware.py`：首次用户消息 → 调模型生成标题（≤12 字）→ 写入会话状态 title
- `thread_data_middleware.py`：before_agent 建 `data/threads/{thread_id}/user-data/{workspace,uploads,outputs}`
- `make_lead_agent` 增加 `tools` / `middlewares` 参数并传入 create_agent

### Step 6：CLI 接入
- 装配时 `get_builtin_tools()` + 两个中间件
- 启动信息加"工具: N 个"（用户之前要求控制台信息更全）
- 标题生成后打印"标题: xxx"

### Step 7：测试（pytest）
- `tests/test_tool_catalog.py`：注册/分层/去重
- `tests/test_middleware_title.py`：标题生成落库（mock 模型）
- `tests/test_stream_chunks.py`：stream 逐块产出（P-016 回归）
- `tests/test_session_repo.py`：M1 欠账补齐

## 6. 参考原版读法（学习点）

1. **工具 docstring 即说明书**：原版每个工具 description 极详细（何时用/何时不用/格式）——模型靠它选工具
2. **return_direct=True**：澄清类工具直接返回，不再回模型循环（原版注释解释了原因）
3. **延迟收集**：get_builtin_tools 用 lru_cache + 函数内 import——启动快
4. **中间件是横向能力**：标题/线程目录不改变主图逻辑，挂在 AgentMiddleware 上

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 5 个工具让模型选错/乱调 | 每个工具 docstring 写清使用条件；验收时人工判断 |
| knowledge 无真实 RAG | 工具返回明确提示"未接入知识库"（结构先对，M5 再接） |
| 标题生成阻塞对话 | 只在首条消息生成一次；失败不影响对话（try/except） |
| 中间件 API 不熟 | 学原版 `AgentMiddleware` + `state_schema` 模式，先读 langchain 源码 |
