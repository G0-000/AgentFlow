# M0 — 环境搭建

**状态：✅ 完成**　**耗时：约 1 天**　**环境：macOS (M2) + VSCode**

---

## 1. 目标

把仿写项目的 Python 开发环境跑通：包管理器、依赖安装、双包结构能 `uv sync` 通过。

## 1.5 环境结构图（M0 的产物长这样）

```
AgentFlow/                          ← 项目根
├── config.yaml                     ← 运行时配置（模型/路径）
├── data/                           ← SQLite 等运行时数据（首次运行自动建）
└── backend/                        ← Python workspace 根（uv sync 在此执行）
    ├── pyproject.toml              ← 应用层包（name=agentflow）★ 两个 pyproject 之一
    │     [tool.uv.workspace] members=["packages/harness"]
    │     [tool.uv.sources] agentflow-harness={workspace=true}
    ├── uv.lock                     ← 依赖锁（版本生态权威，遇冲突先查它）
    └── packages/harness/
        ├── pyproject.toml          ← 核心层包（name=agentflow-harness）★ 之二
        │     [project.scripts] agentflow = "agentflow.cli.main:main"
        └── agentflow/              ← 核心 Python 包（M1 代码都在这）
```

**为什么 2 个 pyproject（原版标准）**：
```
backend/pyproject.toml（应用层）──依赖──► packages/harness（核心层）
   M7 起放 Gateway API / IM 渠道          M1 起放 Agent 运行时（本项目的"心脏"）
```
`uv sync` 在 backend/ 执行一次，同时解析两个包——这正是原版 EvoFlow 的双包 workspace。

## 2. 思考过程（关键决策链）

### 2.1 为什么不是"进入 backend 执行"？

最初被一段通用指引误导：`cd backend && uv sync`。报错 `No pyproject.toml found`。

**结论**：`pyproject.toml` 在哪，`uv sync` 就在哪执行——这是唯一规则。
- EvoFlow 源码把 Python 后端放在 `backend/`（monorepo 布局），所以它要在 backend 下跑
- 自己的项目结构自己定，规则跟着 `pyproject.toml` 走

### 2.2 目录名坑：AegentFlow → AgentFlow

指引里写 `cd /Users/main/AegentFlow/backend`，实际目录已改名 `AgentFlow`，导致 cd 报错。
**教训**：路径用错比命令写错更隐蔽——所有命令先 `ls` 确认真实路径。

### 2.3 单包 vs 双包（workspace）？

- **单包**：`backend/agentflow/` + 一个 pyproject —— 简单，M1 足够
- **双包**：`backend/`（应用层）+ `packages/harness/`（核心层）—— 照搬原版

**决策**：用户选择**严格照搬原版双包结构**。理由：
1. 学习价值：原版就是 gateway（应用）+ harness（核心）分工，对照学习零偏差
2. 未来价值：M7 做 Gateway 应用层时天然分好了层
3. 代价：多一层目录 + workspace 配置，但 M1 已验证可跑通

## 3. 执行步骤（已完成的动作）

```bash
# 1. 装工具（uv 0.12.19 / pnpm 12.6.0 / node v22+ 已有）
curl -LsSf https://astral.sh/uv/install.sh | sh     # uv 装到 ~/.local/bin
npm install -g pnpm                                  # pnpm

# 2. 建双包结构（照搬原版 EvoFlow/backend + packages/harness）
mkdir -p backend/packages/harness/agentflow/{config,models,persistence,agents,tools,cli}

# 3. 两个 pyproject.toml（workspace 成员关系）
#    backend/pyproject.toml         → 应用层，依赖 agentflow-harness
#    packages/harness/pyproject.toml → 核心层，[project.scripts] agentflow = cli

# 4. 安装
cd backend && uv sync
```

## 4. 验证

```bash
ls -d backend/.venv          # ✓ 虚拟环境存在
uv run agentflow --help      # ✓ 入口可执行（M1 提供后）
```

## 5. 坑与教训汇总

| 坑 | 原因 | 解法 |
|---|---|---|
| `cd AegentFlow` 失败 | 目录改名为 AgentFlow | 命令前先 `ls` 确认路径 |
| `uv sync` 找不到 pyproject | 在空 backend/ 执行 | 找到 pyproject 位置再执行 |
| `evoflow-harness ... is not a workspace member` | 只 copy 了 backend/pyproject（单文件），没建 packages/harness | 双包结构必须配套建齐 |
| `uv: command not found`（脚本环境） | uv 装在 ~/.local/bin 未进 PATH | `export PATH="$HOME/.local/bin:$PATH"` 或完整路径 |
