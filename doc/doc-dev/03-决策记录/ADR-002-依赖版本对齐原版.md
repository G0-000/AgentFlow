# ADR-002：依赖版本对齐原版 lock

- **状态**：✅ 已采纳（M1）
- **背景**：`uv sync` 后 import agent 报错：`ImportError: cannot import name 'ExecutionInfo' from 'langgraph.runtime'`

## 问题根因

- 我们 pyproject 约束 `langgraph>=1.0.6,<1.0.10` → uv 装 **langgraph 1.0.9**
- langgraph 1.0.9 自带依赖 `langgraph-prebuilt>=1.0.8,<1.1.0`（约束过宽）→ uv 装 **prebuilt 1.0.13**
- prebuilt 1.0.13 的代码需要 `langgraph.runtime.ExecutionInfo` —— **langgraph 1.0.9 里不存在**
- uv 只看声明约束（认为兼容），运行时才炸

## 排查过程

1. 试 pin `prebuilt==1.0.10` → 仍报错（1.0.10 也要 ExecutionInfo）
2. **查原版 `EvoFlow/backend/uv.lock`** → 原版锁定：`langgraph-prebuilt = 1.0.8`、`langgraph = 1.0.9`、`langchain = 1.2.3`、`langchain-openai = 1.1.7`
3. 对齐原版：`langgraph-prebuilt==1.0.8` → `uv sync` → 问题解决

## 决策

```toml
# packages/harness/pyproject.toml
"langgraph>=1.0.6,<1.0.10",
"langgraph-prebuilt==1.0.8",   # 对齐原版 lock；1.0.9+ 需 langgraph 新 API
```

## 教训（重要）

1. **原版 uv.lock 是版本生态的权威答案**——它锁定的组合是作者验证过能跑的。遇到依赖冲突先查它，不要自己猜版本
2. **pyproject 约束宽 ≠ 兼容**：`>=1.0.8,<1.1.0` 太宽，会拉到不兼容的最新版；关键包要用 `==` 精确锁定
3. 原版没有提交 lock 到我们手边时，版本决策的优先级：**原版 lock > 官方文档示例 > 试错**

## 未来注意

- 升级 langgraph 时（如需要 1.0.10+），要同步验证 prebuilt/checkpoint-sqlite 组合，并重新查原版 lock 是否已换
- M2+ 引入新依赖时，先查原版 harness pyproject 与 lock 的对应版本
