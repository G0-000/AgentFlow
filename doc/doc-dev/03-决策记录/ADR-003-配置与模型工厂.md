# ADR-003：配置与模型工厂设计

- **状态**：✅ 已采纳（M1）
- **背景**：仿写的配置体系怎么设计？原版 config.example.yaml 有 808 行 + 模型配置已迁进 SQLite，照搬显然不现实。

## 决策

**M1 用最简 YAML + dataclass + provider 分发**，保留原版三个核心思想：

```yaml
# config.yaml（M1 版，15 行）
log_level: info
paths:
  data_dir: data
models:
  chat:
    provider: openai-compatible   # GLM / Ollama / LM Studio 通用
    base_url: https://open.bigmodel.cn/api/paas/v4
    api_key: ${ZHIPU_API_KEY}     # 支持环境变量占位
    model: glm-4.7-flash
    temperature: 0.3
```

## 为什么（对照原版思想）

| 原版思想 | M1 落地 |
|---|---|
| yaml → 类型化对象 | `app_config.py` 读 yaml → `AppConfig` dataclass |
| 配置路径可覆盖 | 环境变量 `AGENTFLOW_CONFIG_PATH`（对应原版 `DEER_FLOW_CONFIG_PATH`） |
| `${ENV}` 占位 | `models_yaml.py` 的 `_resolve_env()` |
| 模型按 use 动态加载 | 简化为按 `provider` 分发（`factory.py`），use 字符串机制留 M6 |
| 模型配置进 DB 管理 | **明确不做**：那是原版第二阶段的进化，M7/M8 再学 |

## 关键设计点

- **api_key 不进 yaml 明文**：用 `${ENV}` + `.env`（dotenv 已入依赖），避免把密钥提交进 git
- **paths.py 用 `parents[5]` 定位项目根**：不依赖 cwd，任何目录启动都能找到 data/ 与 config.yaml
- **模型工厂是扩展点**：`provider in ("openai-compatible","openai","zhipu")` 走 OpenAI 兼容；未来加 deepseek/volc 只需在 factory 加分支

## 与原版的差异（明确记录）

- 原版：模型配置存 SQLite（`evoflow_models` 表），页面「设置 → 模型」管理，config.yaml 里 models 段已废弃
- 我们：M1 用 yaml（简单、可读）；**M7 做设置页时迁移到 SQLite**，把原版的进化再走一遍
