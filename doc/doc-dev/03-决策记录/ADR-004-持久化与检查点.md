# ADR-004：持久化唯一属主与检查点

- **状态**：✅ 已采纳（M1）
- **背景**：仿写项目里 SQLite 谁来碰？会话持久化（checkpoint）怎么做？

## 决策

**1. 持久化唯一属主（照搬原版 R1 精神）**

所有 SQL 收口到 `persistence/` 域：`db.py`（连接）→ `schema.py`（表）→ `bootstrap.py`（建表）→ `*_repositories.py`（读写）。其他模块**不直接 import sqlite3**。

```
persistence/
├── db.py            连接管理（WAL + 外键，row_factory=Row）
├── schema.py        表结构 SQL（SCHEMA_SQL 常量）
├── bootstrap.py     幂等建表（IF NOT EXISTS）
├── timestamps.py    统一时间戳（UTC ISO）
├── repositories.py  BaseRepository 基类
└── session_repositories.py  会话/消息 repo
```

**2. 检查点用官方 SqliteSaver（M1），不自研**

原版自研了异步 checkpointer（`agents/checkpointer/` 5 个文件，支持会话搜索/线程状态读取）。M1 直接：

```python
from langgraph.checkpoint.sqlite import SqliteSaver
def make_checkpointer(db_path: str) -> SqliteSaver:
    return SqliteSaver.from_conn_string(db_path)
```

## 为什么

1. **唯一属主是长期健康的根基**：模块多了以后，谁都能碰 DB 就会乱。M1 就立规矩，成本最低
2. **SqliteSaver 是官方检查点**：图状态（含消息历史）自动持久化，一行代码实现"会话可恢复"验收点；自研版等 M2/M3 理解检查点机制后再学原版
3. **会话 repo 存"明文副本"**：checkpointer 存的是图状态（二进制序列化），`session_repositories` 存的 `sessions/session_messages` 是明文记录，未来给 UI 历史/搜索用（M7）。两者分工明确，不冲突

## 表结构（M1）

```sql
sessions          (id PK, created_at, updated_at, title)
session_messages  (id PK AUTOINCREMENT, session_id FK→sessions, role, content, created_at)
```
