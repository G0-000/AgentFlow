# 开发指南（运行 / 调试 / 测试 / 提交规范）

> 所有命令默认在 `backend/` 下执行（workspace 根）。

## 1. 运行

```bash
cd /Users/main/AgentFlow/backend
export PATH="$HOME/.local/bin:$PATH"   # 若 uv 找不到

uv sync                                 # 装依赖（首次/依赖变更后）
uv run agentflow                        # 终端对话（M1 验收入口）
uv run agentflow --thread <id>          # 复用会话（验证持久化）
```

配置：项目根 `config.yaml`（模型地址/名字/key 占位）；密钥放 `.env`（已被 gitignore）。

## 2. 调试

| 场景 | 方法 |
|---|---|
| 快速验证某模块 | `uv run python -c "from agentflow.xxx import ...; print(...)"` |
| 看 Agent 完整输出 | CLI 里逐块打印（M2 前用 print，M2 后有流式） |
| 看 SQLite 内容 | `sqlite3 /Users/main/AgentFlow/data/agentflow.db "select * from sessions;"` |
| 排查依赖 | `uv pip list \| grep langgraph`；报错先查 [06-问题日志/问题日志](../06-问题日志/问题日志.md) |
| 对照原版 | 同功能看 `EvoFlow/backend/packages/harness/evoflow/` 对应文件 |

## 3. 测试规范

- 测试放 `packages/harness/tests/`（核心层）与 `tests/`（应用层，M7 起）
- 命名：`test_<模块>.py`；运行：`uv run pytest tests/ -v`
- **先读原版对应测试再写自己的**（测试即契约）——每里程碑验收清单已列对照文件
- 异步测试：pytest-asyncio（pyproject 已配 `asyncio_mode = "auto"`）

## 4. 代码规范

- **结构**：新文件先找原版对应位置，命名对齐（`xxx_tool.py` / `xxx_repositories.py` / `xxx_middleware.py`）
- **lint**：`uv run ruff check .` + `uv run ruff format .`（项目用 ruff）
- **import 顺序**：标准库 → 第三方 → agentflow 内部
- **注释**：文件头 docstring 写"仿原版哪个文件"（保持对照可追溯）

## 5. git 提交规范

- 项目已 `git init`，`.gitignore` 已排除：`.env` / `config.yaml` / `.venv` / `__pycache__`
- **注意**：`backend/uv.lock` 当前被 ignore —— 建议删掉该行让 lock 入库（否则版本漂移会复现 P-005）
- 提交粒度：按里程碑（M1 完成提交一次），message 如 `M1: 最小Agent闭环（config/models/persistence/agents）`
- 密钥绝不允许进提交（git diff 前自查）

## 6. 新增依赖流程

1. 先查原版 pyproject（`/Users/main/EvoFlow/backend/packages/harness/pyproject.toml`）用哪个版本
2. 加入 `packages/harness/pyproject.toml` 对应分组（带注释：用途 + 里程碑）
3. `uv sync` → 更新 uv.lock
4. 若版本冲突：查原版 uv.lock 的精确版本（见 P-005 / ADR-002）
