## 8. 手动测试补充：一条消息的完整执行链路解剖（2026-09-30）

> **触发疑问**：用户手动测试 M2 时问——"看不到具体执行细节。发消息后，回来的数据如何解析？
> 比如发『帮我记一个待办：学完M2』，如何提取消息，如何知道是待办业务的？"
>
> 本文回答：**模型如何判断调哪个工具、框架如何解析工具指令、CLI 如何提取消息**，
> 用解剖脚本把链路每一层的数据真实打印出来（非讲解，是运行证据）。

### 8.1 解剖工具

脚本：`backend/scripts/debug_agent_trace.py`（教学用，走真实模型 + 真实工具链路）

```bash
cd /Users/main/AgentFlow/backend
.venv/bin/python scripts/debug_agent_trace.py "帮我记一个待办：学完M2"
.venv/bin/python scripts/debug_agent_trace.py "AgentFlow 用什么框架构建？请查知识库"
```

原理（三层观察点）：

| 层 | 怎么看的 |
|---|---|
| 模型调用进出 | 挂 `BaseCallbackHandler`：`on_llm_start` 打印模型**收到的完整 messages**；`on_llm_end` 打印模型**返回的原始响应** |
| 工具执行 | `on_tool_start` 打印工具名 + 参数 JSON；`on_tool_end` 打印返回值 |
| CLI 提取视角 | 逐个打印 stream chunk 的 keys + `_iter_chunk_messages` 挖出的消息类型 |
| 终态 | `agent.get_state()` 打印 messages 完整累积链 |

### 8.2 链路一：todo（return_direct=True —— 直传形态）

**第 0 步：模型"看得到什么"**（系统提示里注入的工具说明书，一字不差）：

```text
模型启动时看到的工具说明书（每个工具的 name + description）:
  - 'ask_clarification': 用于向用户发起结构化澄清（不要只在对话里列选项）。…
  - 'todo': 会话内待办清单工具（对话级 checklist，不是任务中心）。
           当用户要求"列一下要做的事 / 帮我记个待办 / 进度到哪了"时使用。…
  - 'knowledge': 知识库检索工具（统一接口: search / read / list）。…
  - 'fetch_url': 网页抓取工具：给定 URL，抓取并返回页面正文文本（最多 2000 字）。…
  - 'plan': 计划工具：维护当前任务的分步计划（get/update/save）。…
  （模型就是靠 description 决定何时调哪个工具）
```

**第 1 步：模型调用**（收到的 messages = System 人格+时间 + Human 用户消息）：

```text
System: 你是 AgentFlow 的助手（仿写 EvoFlow 的 M3 最小实现）。…当前系统时间：2026-09-30 周三 (UTC+08:00)
Human: 帮我记一个待办：学完M2
```

**第 2 步：模型返回结构化工具指令**（这就是"如何知道是待办"的答案——不是代码判断，是模型读了 todo 的 description 后**自己输出 JSON**）：

```text
模型返回 AIMessage:
  content   = '\n'
  tool_calls = [{'name': 'todo', 'args': {'action': 'add', 'title': '学完M2'},
                 'id': 'call_-xxx', 'type': 'tool_call'}]
```

**第 3 步：框架解析并执行**（框架不"理解"待办，只做：解析 JSON → 按 name 找注册工具 → 按函数签名 schema 校验参数 → 执行）：

```text
工具名: 'todo'
工具收到的参数（JSON 字符串）: {'action': 'add', 'title': '学完M2'}
```

**第 4 步：工具返回，包成 ToolMessage 回填**（`tool_call_id` 标记回应哪一次调用）：

```text
ToolMessage(content='已添加待办: 学完M2（todo-1）', name='todo',
            tool_call_id='call_-7225336483203250265')
```

**第 5 步：return_direct=True → 结果直接作为本轮回复**（模型不再二次加工）：

```text
chunk keys = ['model']  → 挖到 type='ai'   content='\n'（内含 tool_calls）
chunk keys = ['tools']  → 挖到 type='tool' content='已添加待办: 学完M2（todo-1）'
你看到的回复: "已添加待办: 学完M2（todo-1）"
```

**终态消息链**（AgentState.messages 按 reducer 累积，每轮追加不清空）：

```text
- human | '帮我记一个待办：学完M2'
- ai    | '\n' | tool_calls=[('todo', {'action': 'add', 'title': '学完M2'})]
- tool  | '已添加待办: 学完M2（todo-1）' | tool_call_id='call_-xxx'（回应哪次工具调用）
```

### 8.3 链路二：knowledge（return_direct=False —— 引用回答形态）

**差异只在第 5 步**：工具结果不回显，而是**回填后触发第二次模型调用**。

```text
第 1 次模型调用 → tool_calls=[{'name': 'knowledge', 'args': {'action': 'search', 'query': 'AgentFlow 框架'}}]
工具执行 → ToolMessage('检索结果:\n[1] AgentFlow技术栈\n   分数: 0.648\n   AgentFlow 技术栈：后端 Python 3.12 + LangGraph 1.0.6 + …')
第 2 次模型调用（模型带着 ToolMessage 的完整上下文再生成）→
  AI: 根据知识库查询结果，AgentFlow使用以下框架构建：
      技术栈：后端 Python 3.12 / 框架：LangGraph 1.0.6 + LangChain 1.2.3 / 存储：SQLite
```

终态消息链（比 todo 多一条 `ai` —— 第二次模型生成的回答）：

```text
- human | 'AgentFlow 用什么框架构建？请查知识库'
- ai    | '\n' | tool_calls=[('knowledge', {'action': 'search', 'query': 'AgentFlow 框架'})]
- tool  | '检索结果:\n[1] AgentFlow技术栈\n   分数: 0.648\n…' | tool_call_id='call_-xxx'
- ai    | '根据知识库查询结果，AgentFlow使用以下框架构建：…'   ← 引用检索结果的回答
```

### 8.4 关键结论（回答用户疑问）

| 疑问 | 答案 |
|---|---|
| 数据如何解析 | 模型返回的是**结构化 JSON**（tool_calls），不是自然语言——框架按 `name` 找工具、按参数 schema 校验后执行 |
| 如何知道是待办业务 | **模型判断的**：每个工具的 `description`（说明书）注入 system prompt，模型读了"当用户要求帮我记个待办时使用"后自己输出 `todo` 指令 |
| 如何提取消息 | CLI 的 `_iter_chunk_messages` 从 stream chunk 递归挖：`['model']` 块是 AI 消息（含 tool_calls）、`['tools']` 块是工具结果 |
| 工具结果如何回来 | 框架包成 `ToolMessage`（带 `tool_call_id` 配对），回填 messages 追加进对话历史 |
| return_direct 是什么 | True = 工具结果直接作为回复（todo 等结构化结果）；False = 结果回填，模型基于它**再生成一次**回答（knowledge RAG） |
| 消息链为何累积 | AgentState.messages 用 reducer 追加；同一 `thread_id` 再跑，checkpointer 恢复历史继续追加（--thread 续聊机制，脚本重复跑同 ID 正好演示了这一点） |
