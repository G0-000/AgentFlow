# M6 验收清单

> **怎么验收 M6**：扩展（MCP/社区集成）+ 治理（鉴权/可观测）。状态：⏳ 未开始（清单先行）。

## 功能需求（用户视角：系统可扩展、可管控、可观测）

1. 能接入 **MCP 服务器**（外部工具变成本项目工具）
2. 至少有 1 个第三方集成可用（搜索/抓取）
3. **登录鉴权**：未登录访问被拦，登录后可访问
4. **可观测**：一次对话的完整链路可追踪（trace/延迟/日志）

## 代码需求（对齐原版结构）

| 要求 | 对照原版 |
|---|---|
| `mcp/`（stdio/SSE/HTTP 传输） | `evoflow/mcp/` |
| `community/`（至少 1 个集成，如搜索） | `evoflow/community/` |
| `authz/`（授权/主体/可见性） | `evoflow/authz/` |
| `observability/`（追踪/延迟/查询） | `evoflow/observability/` |
| `webui/`（JWT 认证、静态服务） | `evoflow/webui/` |
| 依赖：`langchain-mcp-adapters` 等（M6 取消注释） | 原版 harness pyproject |

## 验收点

| # | 验收点 | 怎么验 | 通过标准 | 状态 |
|---|---|---|---|---|
| 1 | MCP 接入 | 起一个本地 MCP 服务（如 filesystem），Agent 调它的工具 | MCP 工具出现在工具目录并可调用 | ⏳ |
| 2 | 第三方集成 | 问一个需要搜索的问题 | 返回真实搜索结果 | ⏳ |
| 3 | 鉴权拦截 | 无 token 请求受保护接口 | 401；带 token 通过 | ⏳ |
| 4 | 可观测 | 跑一次对话后查 trace | 能按请求查到完整链路/延迟 | ⏳ |
| 5 | 回归 M1-M5 | 重跑 M1-M5 验收清单 | 全部 ✅ | ⏳ |

## 验收不过排查

| 现象 | 处理 |
|---|---|
| MCP 工具不出现 | 传输类型（stdio/SSE/HTTP）；服务器是否在跑 |
| 鉴权失效 | JWT 密钥配置；依赖注入顺序 |
| trace 为空 | 中间件/回调是否注册进图 |
