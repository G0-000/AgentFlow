# M0 验收清单

> **怎么验收 M0**：环境搭建的验收 = 工具齐 + 依赖通 + 入口可执行。
> 实测过程见 [M1-验证记录.md](./M1-验证记录.md)（M0 记录并入其中）。

## 功能需求（环境层面：开发环境就绪）

1. Python/Node 工具链齐备（uv / pnpm / Git）
2. 项目依赖可安装、可重复安装（uv sync 幂等）
3. 命令行入口可用（`uv run agentflow --help`）
4. VSCode 能识别解释器（代码补全/检查生效）

## 代码需求（结构层面：双包 workspace 就位）

| 要求 | 对照原版 |
|---|---|
| `backend/pyproject.toml` 声明 workspace 成员 `packages/harness` | `EvoFlow/backend/pyproject.toml` |
| `packages/harness/pyproject.toml` 独立成包（agentflow-harness） | `EvoFlow/backend/packages/harness/pyproject.toml` |
| `uv.lock` 生成且锁定版本 | 原版 uv.lock（版本生态权威） |
| `config.yaml`（项目根）可被 config 域读取 | 原版 config.example.yaml 的机制 |

## 测试需求

- 环境类里程碑以"命令可复现"代测试：每次搭建/换机后跑一遍下面前置命令确认
- 对照原版：`EvoFlow/README.md` + `backend/README.md` 的安装章节

## 验收点

| # | 验收点 | 怎么验（命令） | 通过标准 | 状态 |
|---|---|---|---|---|
| 1 | uv/pnpm 可执行 | `uv --version && pnpm --version` | 打印版本号 | ✅ |
| 2 | workspace 解析 | `cd backend && uv sync` | 无报错，`agentflow-harness` 可构建 | ✅ |
| 3 | .venv 生成 | `ls backend/.venv` | 目录存在 | ✅ |
| 4 | CLI 入口 | `uv run agentflow --help` | 打印帮助（M1 提供后验证） | 🟡 依赖 M1 |
| 5 | VSCode 解释器 | 打开 .py → 右下角选 `backend/.venv/bin/python` | 补全/检查生效 | 🟡 可选 |

## 验收不过排查

| 现象 | 处理 |
|---|---|
| `uv: command not found` | `export PATH="$HOME/.local/bin:$PATH"`（uv 装 ~/.local/bin） |
| workspace 报错 | 两个 pyproject 的 members/sources 是否配套（见 ADR-001） |
| 依赖版本冲突 | 对齐原版 uv.lock（见 ADR-002） |
