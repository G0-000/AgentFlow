# 验收方法论（05-验收体系 总览）

> 每个里程碑"写完 ≠ 完成"——**验收通过才算完成**。本文档定义怎么验收，每个里程碑产出自己的验收清单。

## 为什么单独管验收

- 防"自我感觉良好"：代码能跑 ≠ 满足验收标准（M1 就出现过：uv sync 过了但 import 炸了）
- 可复现：验收命令固定下来，任何时候能重跑确认
- 可对照：原版测试就是契约，自己的实现要对得上

## 通用验收流程（每里程碑 4 步）

```
① 定验收点    从里程碑目标反推："做到什么才算完成"（一般 3-5 个点）
② 定操作      每个验收点一条可复现命令/操作（能跑、能看结果）
③ 跑并记录    执行 → 记录结果到本目录的「验证记录」文档（报错也记）
④ 对照原版    读原版对应测试，确认"契约"一致（测试即文档）
```

## 验收原则

1. **用户视角优先**：验收点必须是"从外面能感知到"的行为（能对话、能持久化、能流式），不只是"import 不报错"
2. **测试即契约**：原版 `tests/` 的断言在告诉你"这个模块该有什么行为"，对照它定自己的标准
3. **命令可复现**：每项验收写清命令，别人（未来的你）照着跑即可
4. **状态明确**：每项只允许 ✅（通过）/ 🟡（待办，写明差什么）/ ❌（失败，记录原因）

## 文档约定（每里程碑两个文件）

| 文件 | 内容 | 例子 |
|---|---|---|
| `M{X}-验收清单.md` | **标准与步骤**：验收点、怎么验、通过标准、状态 | [M1-验收清单.md](M1-验收清单.md) |
| `M{X}-验证记录.md` | **实测结果**：跑了什么、输出、报错与修复 | [M1-验证记录.md](M1-验证记录.md) |

区别：验收清单是"应该怎样 + 做了没"（活文档，状态会变）；验证记录是"实测发生了什么"（历史存档，写完不动）。
