# 总体设计（AgentFlow 系统设计说明）

> 给接手者看懂的"系统长什么样、数据怎么流"。细节实现见 04-模块实现/。

## 1. 设计目标

仿写 EvoFlow：**LangGraph 驱动的长任务 Agent 运行时**。核心能力演进路径：

```
M1 能对话+持久化 → M2 能调工具+流式 → M3 能记住+查知识 → M4 能派活
→ M5 能跑长任务 → M6 能扩展+治理 → M7 对外 API+IM → M8 有界面
```

## 2. 分层架构（规则 R1）

```
┌──────────────────────────────────────────┐
│  应用层 backend/（M7 建 app/）            │  ← 对外世界（API/IM）
│            │ import agentflow.*（单向）    │
│            ▼                              │
│  核心层 packages/harness/agentflow/       │  ← 业务（agents/tools/...）
│            │ 只经"端口"反向调用（M7 前无） │
│            ▼                              │
│  持久化 agentflow/persistence/            │  ← SQLite 唯一属主
└──────────────────────────────────────────┘
```

**铁律**：核心层永远不能 import 应用层；DB 只有 persistence 域碰。

## 3. 核心概念（必须理解）

| 概念 | 是什么 | 在哪 |
|---|---|---|
| **ThreadState** | 图的状态 dict（messages + thread_id），一切信息在这里流转 | `agents/thread_state.py` |
| **LangGraph 图** | Agent 骨架：节点读写状态，`create_agent(llm, tools)` 生成 | `agents/lead_agent/agent.py` |
| **Checkpointer** | 每步状态自动存 SQLite，同一 thread_id 恢复 | `agents/checkpointer/provider.py` |
| **工具目录** | 工具注册表（schema/分组），Agent 按需加载（M2） | `tools/tool_catalog.py` |
| **中间件** | 横切面（记忆/标题/权限...），挂在 Agent 上（M2） | `agents/middlewares/` |
| **模型工厂** | 按 provider 创建模型（OpenAI 兼容统一入口） | `models/factory.py` |

## 4. 数据流（一条对话怎么走）

```
用户输入
  → CLI/API 层（cli/main.py 或 M7 gateway）
  → make_lead_agent().stream({"messages":[...]}, {thread_id})
  → LangGraph 图：模型想 → 调工具（tool_catalog 里的）→ 看结果 → 再想
  → 每步状态写进 checkpointer（SQLite）
  → 流式 chunk 回传 → 用户看到回复
```

## 5. 请求-持久化对照

| 运行时 | 存储 | 用途 |
|---|---|---|
| Checkpointer（SqliteSaver） | `data/agentflow.db` 的 checkpoint 表 | 图状态（会话可恢复） |
| `persistence/session_repositories` | sessions / session_messages 表 | 会话元信息 + 明文记录（M7 前端用） |

## 6. 模型接入策略

- 所有模型走 **OpenAI 兼容协议**：`config.yaml` 改 base_url + model + key 即可切换
- 已支持：DeepSeek（`api.deepseek.com/v1`）、智谱 GLM（`open.bigmodel.cn/api/paas/v4`）、本地 Ollama/LM Studio
- 向量模型（M3）：云端 embedding 或本地服务，配置驱动（见 ADR-003）
