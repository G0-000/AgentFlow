# 目录结构（对照原版 EvoFlow）

> 规则：**目录层级与命名照搬原版，文件数量按里程碑裁剪**。
> 完整路径：`backend/packages/harness/agentflow/`（对应原版 `backend/packages/harness/evoflow/`）。

## 1. 当前完整目录树（M1）

```
AgentFlow/
├── config.yaml                       # 项目配置（M1：日志/路径/模型）
├── data/                             # 运行时数据（SQLite 等，首次运行自动建）
├── backend/
│   ├── pyproject.toml                # 应用层（gateway）：依赖 agentflow-harness
│   ├── uv.lock                       # 依赖锁（版本生态的权威答案）
│   └── packages/
│       └── harness/
│           ├── pyproject.toml        # 核心层：name = agentflow-harness
│           ├── agentflow/            # 核心包（import 时叫 agentflow）
│           │   ├── __init__.py
│           │   ├── config/           # 配置域（仿 evoflow/config/）
│           │   │   ├── app_config.py      # 全局配置入口
│           │   │   ├── model_config.py    # 模型配置类型
│           │   │   ├── models_yaml.py     # yaml → 模型配置 + ${ENV} 展开
│           │   │   └── paths.py           # 数据路径（parents[5] 定位项目根）
│           │   ├── models/           # 模型域（仿 evoflow/models/）
│           │   │   ├── factory.py         # 模型工厂（按 provider 分发）
│           │   │   └── patched_openai.py  # OpenAI 兼容适配
│           │   ├── persistence/      # 持久化域（仿 evoflow/persistence/，SQLite 唯一属主）
│           │   │   ├── db.py              # 连接管理（WAL + 外键）
│           │   │   ├── schema.py          # 表结构
│           │   │   ├── bootstrap.py       # 幂等建表
│           │   │   ├── timestamps.py      # 时间戳工具
│           │   │   ├── repositories.py    # repo 基类
│           │   │   └── session_repositories.py  # 会话 repo
│           │   ├── agents/           # Agent 域（仿 evoflow/agents/）
│           │   │   ├── thread_state.py    # ThreadState（messages + thread_id）
│           │   │   ├── checkpointer/      # 检查点（会话持久化）
│           │   │   │   ├── provider.py        # SqliteSaver 封装
│           │   │   │   └── async_provider.py # 异步入口（对齐原版命名）
│           │   │   └── lead_agent/         # 主 Agent
│           │   │       ├── agent.py        # make_lead_agent
│           │   │       └── prompt.py       # 系统提示词（时间注入，原版同款文件）
│           │   ├── tools/            # 工具域（仿 evoflow/tools/）
│           │   │   └── builtins/         # 内置工具（M1 空壳，M2 填充）
│           │   └── cli/              # 命令行入口（仿 evoflow/cli/）
│           │       └── main.py           # 终端对话循环
│           └── tests/                # 核心层测试（M2 开始补）
└── doc/                              # 文档库（本开发文档）
    ├── doc-dev/                     # 开发过程文档（里程碑/架构/决策/验收/问题）
    └── doc-code/                    # 代码结构文档（与 agentflow/ 目录一一对应）
    ├── README.md
    ├── 01-里程碑/ 02-架构设计/ 03-决策记录/ 04-模块实现/ 05-验收体系/
```

## 3. 为什么这样分层（对照原版 ARCHITECTURE.md 规则 R1）

```
backend/app（应用层）  →  import agentflow.*（单向）
agentflow（核心层）    →  不反向 import 应用层
persistence/          →  SQLite 唯一属主，其他模块不直接碰 DB
```

M1 还没有应用层（`app/` 目录 M7 建），但核心层已经按这个规则隔离好。
